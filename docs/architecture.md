# Architecture

Personal NixOS + Home Manager flake for `deadPc`, `deadConvertible`, `deadServer`, `deadWsl`, and `deadPi`. Built on flake-parts. `deadRetro` is a NixOS 14.12 KDE 4 VM exposed as an app (`nix run .#deadRetro`), not a `nixosConfiguration`.

## Flake wiring

`flake.nix` only lists inputs and imports `flake/modules/`. Those modules:

- `constants.nix` — `vars` (username, git identity, browser, terminal, keyboard layout) and `hostDefinitions` from `hosts/hosts.nix`. Injected as `_module.args`.
- `exports.nix` — builds the registries and exposes them both as flake outputs (`nixosModules`, `homeManagerModules`, `overlays`) and as `projectOutputs` for internal use.
- `hosts.nix` / `home.nix` — iterate `hostDefinitions` to build `nixosConfigurations` and `homeConfigurations`. Both pass `{ inputs, vars, systems, outputs = projectOutputs }`. Inside any module, **`outputs` is this repo's registry**, not a flake-utils `outputs`.
- `per-system.nix` — formatter, dev shell, git hooks. Also exposes `packages.helium`, `packages.claude-science` (unfree, so it uses a locally-configured nixpkgs rather than the shared `pkgs`), and `apps.deadRetro`.
- `deploy.nix` — deploy-rs nodes for hosts that have `hosts/<name>/deploy.nix`. That file is a plain attrset, not a NixOS module.

## Module → host layering

Everything composes through plain NixOS / Home Manager modules. There are no custom `mkOption` definitions and no profile layer. Hosts import modules directly and spell out the full list.

1. **Modules** (`modules/nixos/`, `modules/home-manager/`): leaf config grouped by domain. Registries are auto-generated by `flake/lib/registry.nix`:
   - `foo.nix` → `foo = import ./foo.nix`
   - `bar/` with `default.nix` → imported as one module
   - `baz/` without `default.nix` → nested registry (omitted when empty)
   Only real module dirs (`windowManager/hyprland`, `flatpak`, `gaming`, `kitty`, `starship`) keep a `default.nix`.
2. **Hosts** (`hosts/<name>/config.nix`, `home.nix`): a flat `imports` list naming every module (`outputs.nixosModules.<domain>.<name>`, `outputs.homeManagerModules.<domain>.<name>`) plus host hardware and overrides. No bundles, no `builtins.attrValues`. `hosts/hosts.nix` maps host name → `{ system, nixosModules, homeModule, enableHome, ... }`.

**To add a module:** create the `.nix` file under the right domain directory (auto-discovered). Then add it to the `imports` of **each host** that should get it — nothing picks modules up automatically. It goes live on the next rebuild once it is `git add`ed. Untracked files are invisible to flake evaluation; keep WIP outside `modules/`.

**To add a host:** add an entry to `hosts/hosts.nix` and create `hosts/<name>/`.

Home configurations are standalone (`flake.homeConfigurations`), so Stylix `homeManagerIntegration.followSystem` never applies. Shared Stylix values live in `flake/lib/theme.nix` and are imported by both the NixOS and Home Manager stylix modules.

## Overlays

`overlays/default.nix`:

- `additions` — custom packages from `pkgs/` as `pkgs.<name>`
- `flake-inputs` — `pkgs.inputs.<flake>` aliases each input's packages
- `modifications` — patches (currently logiops)
- `unstable-packages` — `pkgs.unstable.*` from the `nixpkgs-unstable` input

Wired in `modules/nixos/core/defaults.nix` and `modules/home-manager/core/nixConfig.nix`. nixpkgs 26.05 is the default; pull individuals from unstable via `pkgs.unstable`.

## Custom packages

`pkgs/` is the `additions` overlay. Helium is also a flake package (`nix build .#helium`) so `helium-update` can be verified after a bump. `update.sh` must run against the working tree — a store path is immutable. See [decisions.md](decisions.md) for packaging traps.
